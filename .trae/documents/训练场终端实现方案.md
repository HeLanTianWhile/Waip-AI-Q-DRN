# Waip AI 训练场终端实现方案

## Context

当前 `data/Terminal.py` 是纯文本终端：用户每输入一个字母就调用一次 `main()` 做前向传播，并打印输出字符。项目里唯一的“宠物形象”是 `html/pet/pet.html`（Electron 加载），Python 侧没有任何窗口代码。

本次改造要把终端从“文本模型”改成“具身训练场”：

- 运行 `python data/Terminal.py` 后，选择 Agent，然后打开一个深色训练场窗口；
- 终端里再输入文字不再触发前向传播；
- 宠物在场地内，瞳孔跟随鼠标，`heading` 初始 0°（+X）；
- 每跑完一次前向传播，立即应用三个输出神经元（X、Y、转向），再立即用 100° 光线追踪生成下一轮输入；
- 当前世界是空白的，所有光线都撞到窗口边缘，因此每个输入神经元收到 0；
- 不设固定 tick 定时器，循环速度由前向传播 + 处理耗时决定；渲染仍保持约 60fps 平滑。

> 注意：当前磁盘上的 `Terminal.py` 并没有任何窗口代码。若 IDE 里还有未保存的改动，实施前先保存，避免覆盖。

## 1. 文件改动

### `main/main.py`（改）

1. 删除 `print(Input)`，避免高频刷屏（可保留 `debug=False` 开关）。
2. `Input` 支持整组输入：
   - `dict`：`{输入神经元 IP 索引: 数值}`；
   - `int`：等价于 `{Input: 1.0}`，保持旧调用方语义；
   - `"<blank>"` / `None`：空输入。
3. 注入输入时只累加“有限且非 0”的值。值为 0 且 bias 为负会让 `0 >= bias` 成立，把输入神经元写成 0 而不是 `NOT Activate`，污染后续 pending 列表。
4. 传播改为反向索引，语义不变但速度大幅提升：
   - 每次调用先构建 `outgoing[源] -> [(目标, 权重)]`；
   - 对 `Connection Target` 恰好 2 个且不相同的突触，双向登记；
   - 遍历 `pending_tasks` 时只查 `outgoing.get(i, [])`；
   - 跳过非 2 元、自环 `[i, i]`、字段缺失的坏数据（原 `next()` 会抛 `StopIteration`）。
   - 实测 Test 2（702 神经元 / 2009 突触 / 343 活跃）从约 75ms/tick 降到约 1.6ms/tick。

### `data/Terminal.py`（改）

保留：Agent 列表、`&& create` 新建、三库加载、`main_func` 加载、`save_databases`。

删除：`key` 文本映射、`is_valid_chat_input`、`pick_output_key`、整个 `while True: input("你 > ")` 对话循环。

流程改为：

1. 控制台选择/新建 Agent；
2. 加载三个数据库与 `main/main.py`；
3. `from TrainField import run_trainer`（`data/` 是脚本目录，可直接导入）；
4. `run_trainer(agent_name, cfg, syn, state, main_func, save_databases)`；
5. 窗口关闭后打印已保存并退出。

### `data/TrainField.py`（新建，唯一新文件）

包含三部分：

- `PetModel`：纯逻辑，可无窗口测试；
- 神经网络工作线程；
- `TrainingWindow(QWidget)` + `run_trainer()`。

不新增其他文件；不使用 tkinter、pygame、pywebview，采用已安装的 **PySide6 + QPainter**。

## 2. 坐标与神经映射

坐标系：窗口逻辑像素，原点左上，+X 向右，+Y 向下；`heading` 0° = +X，正角在屏幕上顺时针。

- 宠物中心 `(x, y)`，眼睛半径 `R = 60px`，初始在场地中心，`heading = 0`。
- 三个输出（按 `IP = ["Output", n]` 的 `n` 取，不按排序位置）：
  - `out0`：`x += out0 * 1.0`（1 单位 = 1 逻辑像素）
  - `out1`：`y += out1 * 1.0`
  - `out2`：`heading_total += out2 * 360`，`heading = heading_total % 360`
  - 缺失的 `n` 按 0；`y` 为 `"NOT Activate"` 或非有限数按 0。
- 输入：收集所有 `IP[0] == "Input"` 的神经元的 `IP[1]`，去重排序，得到 N 个输入神经元。把 `heading ± 50°` 均匀分成 N 条光线，按排序后的输入索引逐条对应。
- 光线追踪：从宠物中心向每条光线方向与窗口矩形求交；当前世界无物体，交点都在窗口边缘 → 该神经元输入 `0.0`。`sense()` 返回 `{输入IP索引: 0.0}`。
- 位置越界：位移后把 `(x, y)` 夹在 `[R, 宽-R] × [R, 高-R]`，避免跑出训练场；窗口缩放时重新夹。

## 3. 线程与事件循环

- 神经网络跑在 `threading.Thread`（daemon），Qt 只在主线程。
- 工作线程独占三个数据库，循环：

```
while not stop:
    cfg, syn, state = main_func(cfg, syn, state, inputs)
    outs = read_outputs(cfg, state)
    model.apply(outs)
    inputs = model.sense()
    ticks += 1
    每 15 秒: save_callback(...)
    每 8 tick: time.sleep(0)   # 让出 GIL
```

- 共享状态只用一把 `threading.Lock` 保护轻量快照：`(x, y, heading, heading_total, outs, ticks, rate, arena_w, arena_h)`。GUI 通过 `QTimer(16)` 读快照后 `update()`，绝不在 GUI 线程读数据库。
- `sys.setswitchinterval(0.001)`，降低 GUI 最坏停顿。

## 4. 渲染（参考 pet.html）

绘制顺序：

1. 深色场地背景 `#0b0f16`；
2. 16 个 `w`：绕眼睛中心、半径 `1.47R` 均布，整体旋转角取 `heading_total`（转向可见）；每个 `w` 反向旋转保持直立，并按到瞳孔的距离缩放：`S_NEAR=2.2`、`S_FAR=0.6`、`NEAR_D=0.97R`、`FAR_D=1.55R`；
3. 白色大圆 + 黑色边框（边框约 `0.06R`）；
4. 两条竖线瞳孔：跟随鼠标方向，最大偏移 `0.5R`，用 0.14 系数平滑；
5. 左上角 HUD：Agent、tick/s、x/y、heading、out0-2。

鼠标：每帧 `QCursor.pos()` + `mapFromGlobal`，换算成相对宠物中心的方向；鼠标移出窗口仍可跟随。

高 DPI：全部使用 Qt 逻辑像素，不混用 `devicePixelRatio` 缩放后的坐标。

## 5. 退出与保存

- `Esc` 与窗口关闭按钮都走 `closeEvent`：
  1. `stop_event.set()`；
  2. 工作线程在 `finally` 中调用 `save_callback` 写三个 JSON；
  3. `join(5)`；
  4. 关闭窗口。
- 运行中每 15 秒由工作线程保存一次（约 20ms，不碰 GUI）。
- 若 5 秒未退出，打印警告，提示以最近一次周期保存为准。

## 6. 验证

可自动化：

1. 无窗口单步：`PetModel` + Test 1（1 输入 / 1 输出 index=2）
   - 首 tick 后 `out2` 取自 `0002`；`heading` 按 `out2 * 360` 变化；
   - 但 `main()` 会把无输入的 `0002` 置回 `NOT Activate`，因此第二 tick 起输出为 0、宠物静止，属预期。
2. Test 2：断言 N=51 条射线、x/y/heading 有限且在界内、tick/s > 300。
3. 数据库：关闭后 `json.load` 三个文件成功、mtime 更新；连续开关 5 次无线程警告。

人工观察：

- `python data/Terminal.py` → 选 Test 2 → 深色场地出现眼睛，瞳孔跟随鼠标；
- HUD 的 tick/s 持续刷新；
- 有输出时宠物平移/转向，w 环绕随 heading 转动；空白世界光照输入全 0。

## 7. 风险与注意

- Agent 规模不固定（Test 1 只有 1 输入 / 1 输出，Test 2 为 51/51），所有映射必须动态，不能写死 53。
- 输出 `y` 可能是字符串 `"NOT Activate"`，必须 `isinstance` 判断并转 0。
- 突触数据可能非 2 元、含自环或字段缺失，需跳过。
- 输出可能是 `NaN/inf`，必须丢弃，否则坐标会变成 NaN。
- 工作线程必须能及时退出；所有共享数据用锁或快照。
- PySide6 高 DPI 下统一用逻辑像素。
- 高频循环会占满一个 CPU 核心，这是“不设固定定时器”的预期代价；渲染线程独立，界面不卡。
